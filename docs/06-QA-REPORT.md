## Bugs this QA found and fixed (kept here on purpose)

0. **The recovery register counted the same money twice.** Event recoveries were held in one list and policy recoveries in another, and the utilisation statement summed both while the reconciliation summed a third figure. A test caught `1,200,287.50` where the receivable was `150,785.44`: the catastrophe recovery was in the total twice. Fix: **one** recovery register keyed by source (`policy`, `event`, `deposit`), every statement derived from it, and deposit draws marked settled and taken out of ageing and out of the receivable — a deposit draw is already the reinsurer's money. Regression tests: the ageing, reconciliation and deposit-draw cases in `reinsurance.test.ts`.

1. **A data-quality control that could never fire.** REINS-001 reported a reinstatement on a treaty with no annual premium — unreachable, because the register refuses such a treaty in the first place. Removed rather than kept as decoration: a control that cannot fire is not evidence of anything.

2. **Funds withheld was first posted as if cash had moved.** The restricted-cash line counted every on-balance-sheet instrument, including premium withheld — where no money moves at all, only the payable falls. The reconciliation caught it immediately (register 1,500.00 against a books figure of 0.00 in an account nobody had debited). Cash security and withheld premium are now separated: the asset counts cash alone, the liability counts both, and both halves are asserted in `reinsurance.test.ts`.

3. **Four controls that compared the wrong two things.** Building the return's controls found four of them comparing figures that could never agree, and each was rebuilt rather than muted: the claims reserve control compared the ceded-risk subset against the whole reserve account (now the module's reserves are compared claim by claim, with the ceded subset stated as a memorandum); the recoveries control compared reinsurance money against an account that also holds salvage and third-party money (now that money is taken out, and the detail says how much); the security control compared letters of credit against a cash account (now only cash is tied, and the disclosed total is named); and the payable control compared a stock at the reporting date against a total that included earlier periods. A control that cannot agree is not evidence, and a control that always fails is not a control.
4. **A ratio reported as a currency.** Loss ratios were first carried as a `Money` with the currency "BPS", which is one careless screen away from printing a percentage as dirhams. Ratios now have their own cell type and one formatter, and a test asserts `400.00%` formats as a percentage and `250.00 AED` as an amount.
5. **An unreachable version check.** The rule that an extract cannot be dated earlier than the one it replaces was written before the code path existed; the test now drives it and the path is exercised.
6. **An id could be re-used for a quietly different journal.** `Ledger.post` treated an id as a retry when entity, source and postings matched, so a second journal with the same postings but a different timestamp, reference or description was swallowed as a duplicate — money-safe today, but it would have hidden a real duplicate-key bug. The identity check now covers entity, source, source reference, economic time, fund, reversal link, description and postings; the restore path double-checks the journal count so a collapsed journal cannot pass. Test: `persistence.test.ts` ("keeps the id-collision guard on restore").

7. **Journal id collision silently dropped money.** The unit-linked engine and the takaful engine each numbered journals from 1, so on a shared ledger the takaful entries reused ids the unit-linked engine had already posted, and the ledger's idempotency rule discarded them. Symptom: a takaful contribution reduced to a single cash movement — the tabarru, investment and operator legs vanished. Fix: ids are prefixed per module (`UL-…`, `TKF-…`) **and** `Ledger.post` now refuses an id reused for different content instead of silently returning the old entry. Regression tests: `ledger.test.ts` ("the silent-loss trap") and the "two engines, one ledger" money-proof case.

8. **Fractional basis points truncated to zero in daily accruals.** 150 bps / 365 became 0 bps. `applyBps` now works to micro-basis-point precision.

9. **`nextBusinessDay` returned the same day when the date given was already a business day.** which made after-cut-off instructions price on the wrong day. Now strictly after, with the weekend-skip case asserted.

10. **Amount parsing rounded against the customer for fractional digits beyond the currency scale.** `1,234.567` became `1,234.13`. Now the beyond-scale digits round half-up as a whole.

11. **Fund amounts double-typed (minor units vs micro-units).** caught by tests before it reached the console — the unit conventions are now documented in `src/core/units.ts` and asserted.

## How the fleet proves its own claims

`node tools/fleet.mjs` claims a backlog chunk only when (a) its module is implemented, (b) its capability text matches something actually built, and (c) the evidence files exist and the module's test file passes. Everything else stays open — currently **1211 chunks done, 659 still open** on the critical path alone (1870 chunks; the RI rows claimed by the fleet are each named against the file that proves them in `ledger/runs.jsonl`, and `RI-STORE-000892` was reopened because the extracts, the rule book, the wording book and the submission log all run in memory — a schema and migrations for them are not built), and two of the capability-10 rows for this module (`RI-DESIGN-000889` … `RI-DOCS-000896`) were marked claimed by an earlier fleet pass before their work existed; they are only counted as done here because the code, tests and documents for them are now in the repository — the lesson is recorded so the claim rule is judged on what exists, never on what a keyword matched. The ledger at `ledger/runs.jsonl` records every claimed chunk with its evidence and simulated cost, one row per chunk, and `backlog/status.jsonl` is the machine-readable state.

* The tariff is **seeded, not invented** — `seedRatingGrid` derives each product's bands from the tariff it
